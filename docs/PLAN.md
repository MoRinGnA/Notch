# Notch 기능 계획

Windows 상단 상태 아일랜드입니다. 접힘과 펼침 두 상태가 있으며, 이 문서는 디자인 원칙과 현재 동작, 제거된 기능, 남은 계획을 기록합니다.

## 디자인 원칙

- **노치 모양 변화로 정보를 표시합니다.** 미디어 재생과 시스템 상태에 따라 같은 노치가 모양을 바꿔 보여줍니다.
- **HUD 스캔라인:** 미디어가 없을 때 펼친 시스템 HUD에 정적인 가로 스캔라인 오버레이를 표시합니다. 미디어 패널에서는 노치 전체 오버레이를 숨깁니다.
- **상태 점 없음:** 배터리 점 표시는 폐기했습니다. 배터리는 접힌 노치 오른쪽의 `LOW` 배지·충전 번개와 펼친 화면 문구로만 알립니다. CPU 온도는 펼침 HUD에서 보여줍니다.
- **포인트 컬러:** 시계/HUD와 배터리 `LOW`는 고정 `--notch-accent`(#e8833a)를 씁니다. 미디어 가사 빛살은 현재 표시 중인 세션의 YouTube 썸네일 또는 Spotify 앨범 아트에서 뽑은 대표색을 쓰고(일시정지 중에도 유지), 미디어가 사라지거나 유효한 표지색이 없을 때만 고정 주황으로 돌아갑니다. 두 색 계열은 서로 독립입니다.
- **표시 우선순위:** 활성 미디어 세션이 있으면 미디어 패널을 보여주고, 미디어가 없으면 시계와 시스템 상태 HUD를 보여줍니다.
- **접힌 노치 미디어 표시 (결정):** 재생 중(Playing)인 세션이 있을 때 접힌 노치가 가로로 길어져도 됩니다. 크기 고정 제한은 이 항목에서 풀어 둡니다.

## 현재 상태 (완료)

- 투명 프레임리스 창 900x340. 접힘은 154x40(가사에 따라 최대 860), 펼침은 미디어 또는 HUD 화면 600~860x280
- **펼친 화면:** 내비게이션 없이 미디어 상세 또는 시스템 상태 HUD를 표시합니다. 어떤 화면을 띄울지는 활성 미디어 세션 여부에 따라 결정합니다.
- **중복 실행 방지:** 앱을 두 번 열면 같은 설정 파일을 서로 덮어쓰므로 두 번째 실행은 기존 창을 보여주기만 하고 종료한다.
- 노치 실제 크기에 맞춰 Windows 클릭 영역을 제한(`setShape`). 투명 영역은 클릭이 통과합니다.
- 앱 아이콘: `scripts/make-icon.mjs`로 노치 눈 모양 아이콘(`assets/icon.ico`·`icon.png`·`tray.png`)을 코드로 그리고, exe·트레이·창 아이콘에 쓴다(`npm run icon`으로 재생성). 바탕화면 exe의 이름·설명·회사명도 채워져 있다.
- 시스템 트레이 메뉴에서 호버 펼침·전체화면 숨김(기본 꺼짐, 선택 시만 숨김)·펼침 단축키 설정과 Notch 종료. 메뉴에 독점 전체화면 게임 위 표시는 일반 창으로 지원하지 않는다고 안내합니다.
- 평면 눈 애니메이션
- 펼침 HUD: 시계·날짜, CPU 온도(85°C 이상은 흑백 반전 경고), 데스크탑 GPU 사용률, 날씨와 IP 기반 도시명 (미디어가 없을 때는 HUD만 표시). 온도는 LibreHardwareMonitor/OpenHardwareMonitor의 CPU 센서를 먼저 씁니다. 없으면 관리자 권한이 필요 없는 성능 카운터 `Win32_PerfFormattedData_Counters_ThermalZoneInformation`에서 CPU 표기가 있는 열 구역을 우선 조회하고, `HighPrecisionTemperature`(0.1K)가 비었거나 범위를 벗어나면 `Temperature`(K)로 대체합니다. 마지막으로 관리자 권한이 필요한 `MSAcpi_ThermalZoneTemperature`를 시도합니다. 유효 범위는 15~115°C이며 실패 결과는 12초만 캐시해 HUD 폴링에서 재시도합니다. ACPI 열 구역 값은 CPU 다이 온도와 다를 수 있으므로, 값을 읽은 경로도 함께 전달해 CPU 센서·CPU 표기 열 구역은 `CPU`, 마지막 ACPI 폴백은 `ACPI`로 표기합니다(라벨 너비를 4칸으로 맞춰 숫자 열은 움직이지 않습니다). 읽을 수 없으면 `--`로 둡니다.
- **볼륨 채널 (완료):** 시스템 마스터 볼륨을 한 줄짜리 미니 계기판으로 줄여 따로 행을 잡지 않습니다. HUD에서는 맨 아래 정보줄 왼쪽에 `CPU`·`GPU`, 오른쪽에 `VOL`+레일+판독값+`M` 스위치를 나란히 두고, 미디어 패널에서는 재생 버튼 줄을 3칸 그리드로 나눠 버튼은 정중앙, 계기판은 오른쪽 끝에 앉힙니다(레일 폭 88~96px, 높이 17px). 두꺼운 막대 대신 1px 기준선과 1px 채움, 10%마다 짧은 눈금(50%마다 긴 눈금), 끝에 7x5 노브를 얹은 1px 바늘, 3자리 판독값, 음소거는 흑백이 반전되는 작은 `M` 스위치로 값을 읽습니다. 채움과 바늘에만 포인트 컬러를 쓰고(미디어 재생 중에는 표지 대표색, HUD에서는 고정 주황), 눈금·판독값·플레이트는 흑백으로 둡니다. 음소거하면 포인트 컬러가 빠지고 판독값이 가라앉으며 반전은 `MUTED` 플레이트 하나에만 줍니다. 막대를 클릭하거나 끌어 조절하고, 방향키 ±2(Shift ±10)·Home/End·`M` 키를 지원합니다. 마우스를 올리면 목표 지점에 반투명 바늘이 서고 판독값이 목표 숫자로 바뀝니다. 음소거 상태에서 볼륨을 만지면 Windows처럼 소리가 되살아납니다. 조작은 화면에 즉시 반영되고(전환 효과 없이 기계식으로 튐), 펼친 동안에는 300ms 간격으로 시스템 값을 다시 읽어 미디어 키·다른 앱의 변경도 바로 따라옵니다. 시스템에 쓰는 동안에는 조회를 멈춰 늦게 도착한 옛 값이 방금 바꾼 값을 되돌리지 않게 했고, 커서 모양은 바꾸지 않습니다.
- **볼륨 제어 경로 (사이드카):** Windows Core Audio를 C#(`native/audio/Program.cs`)으로 직접 다루는 작은 exe를 앱과 함께 띄워 두고 stdin/stdout으로만 대화합니다. PowerShell + `Add-Type`을 매번 컴파일하던 방식은 첫 호출이 1~2초 걸리고 유휴 시 프로세스를 따로 정리해야 했는데, 미리 컴파일한 .NET Framework exe로 바꿔 그 비용을 없앴습니다(Windows 10/11에 .NET Framework 4.x가 기본 포함). `npm run audio:build`가 Windows 기본 `csc.exe`로 `native/audio/bin/notch-audio.exe`(약 15KB)를 만들고, `npm run build`·`dist:win`에 포함되며 패키지에서는 `extraResources`로 `resources/notch-audio.exe`에 들어갑니다(개발 경로와 패키지 경로를 `app.isPackaged`로 구분). 프로토콜은 요청 ID를 붙인 한 줄 명령(`<id> state|apps|master.set N|master.mute 0/1|app.set pid N|app.mute pid 0/1|device|ping|quit`)과 `<id> ok [payload]`·`<id> err <메시지>` 응답, 그리고 id 없는 `event device <id>|<이름>` 이벤트로 이루어집니다. 앱이 뜰 때 시작해 종료할 때 `quit`로 정리하고, 장치 변경 이벤트를 놓치지 않도록 펼침 여부와 무관하게 유지합니다. 값을 읽지 못하면 `---`로 두고 마지막 값을 유지합니다.
- **앱별 볼륨 (완료):** 마스터 계기판의 `VOL` 라벨이 곧 열기 버튼입니다(미디어 화면에서도 라벨을 숨기지 않아 어느 화면에서든 같은 자리에서 열립니다). 누르면 펼친 패널이 SOUND 화면으로 바뀌고, 맨 위에 `MASTER` 줄을 고정한 뒤 1px 구분선을 두고 그 아래에 기본 출력 장치에서 실제로 소리를 내는(Active) 세션을 앱마다 한 줄로 보여줍니다. MASTER와 앱 모두 `이름 · 1px 레일+눈금+바늘 · 3자리 판독값 · M 스위치`로 같은 규칙을 쓰고, 위계는 구분선 위/아래 위치와 MASTER 이름의 밝기로만 드러냅니다. 레일을 끌거나 방향키(±2, Shift ±10)·Home/End·`M` 키로 그 앱만 조절하고, 음소거하면 포인트 컬러가 빠지고 `M`이 흑백 반전됩니다. 조작은 화면에 바로 반영하고 IPC는 70ms마다 앱별 마지막 값만 묶어 보내며, 800ms 간격 폴링은 끌고 있는 동안 건너뜁니다. 시스템음(pid 0)과 만료된 세션은 빼고, 같은 프로세스의 여러 세션은 한 줄로 합칩니다.
- **앱별 활동량 미터 (완료):** SOUND 화면의 앱 줄 아래에 1px 높이의 가로 막대를 깔아 그 앱의 실제 피크 레벨을 보여줍니다. 이름·음량과 같은 목록을 800ms로 다시 읽는 대신 사이드카에 `peaks` 명령을 따로 두어(프로세스 이름·음량 조회 없이 `IAudioMeterInformation`만 읽음) 화면이 열려 있는 동안 120ms 간격으로 가볍게 받습니다. 떨어질 때 바로 0이 되지 않도록 직전 값의 68%를 남기고 CSS `width` 110ms 전환으로 부드럽게 이어, 채워지는 순간과 줄어드는 꼬리가 모두 읽힙니다. 막대는 줄의 포인트 컬러를 45% 투명도로만 쓰고(음소거된 줄은 18%), MASTER 줄에는 그리지 않습니다. 줄 아래 3px 띄어 다음 줄과 겹치지 않습니다.
- **출력 장치 변화 알림:** 사이드카가 `IMMNotificationClient`를 등록해 기본 출력 장치 변경을 이벤트로 받고(창 메시지에 의존하지 않음), ID가 바뀌었을 때만 알립니다. 펼친 화면에는 `OUT · 장치 이름 [SETTINGS]` 한 줄을 9초 동안 두고(누르면 Windows 사운드 설정), 접힌 화면에서는 `LOW`와 같은 자리에 `OUT` 배지만 9초 동안 띄웁니다. 장치 ID는 기본 출력 장치의 엔드포인트 ID를 쓰고, 표시 이름은 같은 기기의 `MMDevices\Audio\Render\{guid}\Properties`에서 `{a45c254e-…},2`(FriendlyName)를 읽습니다. 장치를 자동으로 바꾸거나 블루투스 재연결을 시도하지는 않습니다. 회의 앱을 추정해 음량을 자동으로 낮추는 덕킹도 넣지 않았습니다(아래 후순위).
- **클립보드 기록 (완료):** 복사한 텍스트를 노치에서 바로 다시 꺼내 씁니다(`Win+V`를 찾아 여는 대신). 펼친 화면의 `CLIP` 라벨(HUD는 `CPU`·`GPU` 옆, 미디어 화면은 버튼 줄 왼쪽)로 열고, 목록에서 줄을 누르면 그 내용이 클립보드로 들어가 줄이 흑백 반전되며 `COPIED`로 바뀝니다. 최대 20개, 같은 내용은 맨 위로 올리고 중복으로 쌓지 않으며, 600ms 간격으로 클립보드를 읽어 비교합니다(변경 이벤트가 없음). 목록은 **메모리에만** 두고 파일로 저장하지 않으므로 앱을 끄면 비밀번호 관리자 등이 넣은 값도 남지 않고, `CLEAR`로 즉시 비울 수 있습니다. 미리보기는 공백을 접은 한 줄 160자이고, 20,000자를 넘는 내용은 담지 않습니다. 화면은 앱별 볼륨과 같은 머리·목록·발 구조를 씁니다.
- **게임 중 음성 상태 (완료):** Discord 로컬 IPC(`\\.\pipe\discord-ipc-0`)에 붙어 `GET_VOICE_SETTINGS`(mute/deaf), `SPEAKING`(내 발화), `VOICE_CHANNEL_SELECT`(채널 입장/퇴장) 이벤트를 **폴링 없이** 받습니다. 음성 채널에 있을 때만 접힌 노치 오른쪽에 작은 마이크 아이콘을 표시하고, 펼친 HUD/미디어 화면에서는 `CLIP` 옆에 같은 아이콘을 둡니다. 아이콘은 `currentColor`로 그려 포인트 컬러를 그대로 따릅니다(이모지는 검정 본체에서 어둡고 생김새가 화면과 안 맞아 뺐습니다). 켜짐은 채운 마이크, 음소거는 흑백으로 죽인 몸통 위에 흰 사선, 말하는 동안에는 같은 포인트 컬러의 음파 두 개가 차례로 점등됩니다. 미디어·가사·HUD 화면 구성은 그대로 두므로 통화 중에도 곡 정보가 유지됩니다.
- **음소거 토글 (완료):** 아이콘을 **클릭하면 마이크 음소거**, **우클릭하면 헤드셋(deafen) 음소거**가 디스코드에 그대로 걸립니다(게임 중 `Alt+Tab`으로 디스코드를 열 필요가 없음). 접힌 노치와 펼친 화면의 같은 아이콘이 모두 같은 동작을 합니다. 디스코드는 헤드셋을 끄면 입력도 함께 끄므로, 헤드셋이 꺼져 있는 동안의 클릭은 헤드셋부터 되살립니다(음소거에 끼이지 않게). 구현은 `SET_VOICE_SETTINGS` 한 줄을 **이미 열려 있는 IPC 소켓에 그대로** 보내는 방식이라 폴링도, 추가 프로세스도, 주기 작업도 없습니다. 성공해야 화면을 바꾸고(실패는 한 줄 경고만), 확인 이벤트가 오기 전에도 바로 반응하도록 먼저 반영합니다. **맞히기 쉬운 클릭:** 글자는 17px 그대로 두고 보이지 않는 `::before` 패딩으로 히트 영역만 약 35x35px로 넓혀(레이아웃 변화 없음), 게임 중에도 정확히 맞힙니다. 아이콘으로 마우스가 곧장 들어오면 노치를 펼치지 않고, 아이콘에서 난 클릭은 상위로 전파되지 않아 노치가 **고정되지 않습니다**(펼치면 아이콘이 움직여 엉뚱한 곳을 누르게 되는 문제 방지). **실측:** 클릭으로 `muted` true↔false, 우클릭으로 `deafened` true↔false가 실제 디스코드 상태와 함께 바뀌었고, 헤드셋을 풀어도 원래 음소거 상태가 보존됩니다. **버린 방식:** Windows 알림 센터 토스트를 2.5초마다 읽는 안은 구현했다가 걷어냈습니다. 토스트 1회 조회가 약 1.4초(기동만 0.27초) 걸려 2.5초 간격이면 사실상 PowerShell이 계속 떠 있는 셈이라 "시스템에 무리를 주지 않는다"는 조건을 못 맞춥니다. **인증:** RPC는 `client_id`만으로는 `4006 Not authenticated`로 막히고, `rpc.voice.read` 스코프는 승인된 앱 전용이라 `invalid_scope`가 납니다. `rpc` 스코프는 앱 소유자에게 열려 있어 이것을 씁니다. PKCE는 이 경로에서 거부되므로(`redirect_uri`를 요구했다가 "RPC 흐름에서는 쓸 수 없다"고 거절) authorization code를 `client_secret`으로 교환합니다. `client_id`/`client_secret`/`refresh_token`은 exe가 아니라 `%APPDATA%\Notch\discord.json`에만 두고, 실행 시 refresh로 갱신합니다(승인 창은 최초 1회, 유효기간 7일). `client_secret`은 저장소 루트의 `.discord-secret.txt`에서 한 번만 읽어 이 파일을 만드는 데 썼고, 그 파일은 `.gitignore`에 넣었습니다.
- **다른 PC에서 디스코드 연결 (완료):** 인증 정보는 `%APPDATA%\Notch\discord.json`에만 두므로 다른 PC에는 처음에 없습니다. 예전처럼 이 파일을 복사하면 두 PC가 같은 갱신 토큰을 쓰다가 한쪽이 회전시킨 순간 다른 쪽이 죽었습니다. 이제 트레이 → `Discord 연결…`이 노치에 `DISCORD` 화면을 열고, 클라이언트 시크릿을 한 번 넣으면 디스코드 클라이언트 안에 뜨는 승인 창에서 허용을 누르는 것만으로 **그 PC 전용 토큰**이 발급·저장됩니다. 브라우저 OAuth 대신 RPC `AUTHORIZE`를 쓰는 이유는 `redirect_uri` 등록이 필요 없어 개발자 포털을 건드리지 않아도 되기 때문입니다(브라우저 방식의 PKCE는 토큰 갱신에 공개 클라이언트 설정이 필요해 포털 접근 없이는 안전하지 않습니다). 연결에 성공하면 기존 소켓을 버리고 새 인증으로 바로 다시 붙습니다. 시크릿은 채팅·저장소에 남기지 않고 그 PC의 `discord.json`에만 들어갑니다. **실측:** 화면 표시(폭 556px, 넘침 없음), 빈 값 버튼 비활성, 짧은 값 거절과 빨간 안내 확인. **미확인:** 실제 승인 → 토큰 발급은 디스코드 창을 사람이 눌러야 해서 자동 검증하지 못했습니다.
- **디스코드 전용 화면 (완료):** 음성 채널의 참가자를 전용 화면에서 봅니다. 브리지가 `GET_SELECTED_VOICE_CHANNEL`의 `voice_states`에서 이름(서버 별명 → 표시 이름 → 계정 이름), 마이크·헤드셋 상태를 읽고, `VOICE_STATE_CREATE/UPDATE/DELETE`를 구독해 입장·퇴장·상태 변화를 **실시간**으로 반영합니다(폴링 없음). 펼친 패널의 `VOICE` 라벨로 열고 채널 이름·인원·참가자 목록(말하는 사람만 밝게)과 하단 `MUTE`/`DEAFEN`/`CLOSE` 버튼을 둡니다. 접힌 노치에는 자리를 새로 만들지 않고, **다른 사람이 말할 때만** 마이크 아이콘 왼쪽 빈자리에 이니셜 최대 두 글자가 잠깐 뜹니다(폭·가사 위치 불변). `SET_VOICE_SETTINGS`로 바꾸면 `VOICE_STATE_UPDATE`가 오지 않으므로, 낙관적으로 내 줄 상태까지 함께 고칩니다. **실측:** 패널 내용과 `MUTE`/`UNMUTE` 동작 확인. 다른 사람의 발화 이니셜은 채널에 혼자 있어 미확인.
- 미디어 패널은 Windows 미디어 세션이 있을 때 표시합니다. 브라우저의 유튜브와 온라인 강의 등도 포함합니다.
- 드래그 선택 차단 (`user-select: none`)
- **접힌 미디어 표시:** 왼쪽에 가수(8px 대문자)·제목(11px), 1px 세로 구분선, 오른쪽에 현재 가사(12px). 곡의 가장 긴 가사 줄 폭으로 노치 폭을 한 번 정하고 곡 동안 유지하며, 긴 가사는 말줄임하지 않고 창 폭 안에서 늘어납니다. 가사 줄이 비면 직전 가사를 유지합니다.
- **펼친 가사:** 같은 곡의 가장 긴 줄이 두 줄로 접히지 않도록 펼친 폭도 계산해 넓힙니다. HUD로 바뀌면 가사 폭을 물려받지 않고 기본 600px로 돌아옵니다. 미디어를 펼친 화면에서는 `NOTCH` 문구를 숨기고 충전·배터리 부족일 때만 그 자리에 표시합니다.
- **가사 조명 효과:** 펼친 가사 위로 미디어 표지에서 추출한 대표색 빛줄기가 지나갑니다(흑백·저채도 표지는 고정 주황으로 폴백하며, 표지색은 HSL 밝기를 최소 82%로 올려 검은 배경에서 보이게 합니다). 속도는 고정 시간이 아니라 해당 줄의 실제 재생 구간에 묶여 있고, 줄 시작에 왼쪽 끝·줄 끝에 오른쪽 끝에 닿습니다. 재생 위치에서 계산한 마스크 위치를 250ms마다 선형 보간으로 갱신하며, 일시정지하면 그 자리에 멈춥니다. 좌우 빛 밴드는 조금 좁히되 펼친 화면은 접힌 화면보다 넓게 퍼지도록 조정했습니다.
- **가사 조회:** 펼침 여부와 무관하게 곡이 바뀌면 조회합니다(접힌 화면에서도 가사 표시).
- **접힌 가사 조명:** 접힌 노치 가사에도 같은 미디어 대표색 빛살이 흐릅니다. 펼친 가사와 같은 재생 위치 계산을 그대로 쓰고, 빈 줄(간주)에서는 이전 가사는 남기되 빛은 두지 않습니다. 빛 밴드 폭을 조금 줄였습니다.
- **여닫힘 애니메이션:** 폭·높이는 과하게 튀지 않도록 짧게 전환하고, 패널이 짧게 따라 나타납니다. 모션 감소 설정을 지원합니다.
- **트레이 설정:** 트레이 아이콘 메뉴에서 바로 바꿉니다. `마우스 올리면 펼치기`·`전체화면에서 숨기기`(기본 꺼짐) 체크박스와 `펼침 단축키` 하위 메뉴(`Ctrl+Alt+N`·`Ctrl+Shift+N`·`Ctrl+Alt+Shift+N`·`사용 안 함`)가 있고, 바꾸면 즉시 적용되어 앱을 다시 실행할 필요가 없습니다. 독점 전체화면 게임 위 표시는 일반 창으로 지원하지 않는다는 메뉴 안내를 둡니다. 값은 `%APPDATA%\Notch\settings.json`에 저장되어 다음 실행에도 유지됩니다(파일은 저장용이며 직접 고칠 필요 없음).
- **창은 클릭해도 활성화되지 않습니다(`focusable: false`):** 노치에서 클립보드 항목을 고른 뒤에도 사용자가 보던 앱이 그대로 앞에 있어야 바로 붙여넣을 수 있습니다. 그 대신 볼륨 레일의 방향키·Home/End·`M` 키는 창이 키보드를 받지 못해 동작하지 않습니다(마우스로 조절).
- **화면 동작:** 마우스를 140ms 올리면 펼쳐지고, 벗어나면 320ms 뒤 접힙니다. 클릭으로 고정/해제, 전역 단축키 `Ctrl+Alt+N`으로도 고정/해제합니다. 버튼 포커스는 자동 접힘을 막지 않습니다. 노치 밖에 마우스가 있을 때 고정을 풀면 다음 호버는 바로 열립니다.
- **전체화면 표시:** 기본값은 전체화면에서도 Notch를 표시합니다. 원할 때 트레이의 `전체화면에서 숨기기`를 켜면 3초마다 앞쪽 창이 모니터를 덮는지 보고 숨깁니다. 구버전 설정은 한 번만 새 기본값(표시)으로 마이그레이션하며, 이후 사용자가 선택한 값은 유지합니다. 이 설정은 독점 전체화면 게임 위 표시를 가능하게 하지는 않습니다(일반 창은 게임이 디스플레이를 직접 제어할 때 그려질 수 없음).
- **접힌 빛의 줄 전환:** 줄이 바뀔 때 빛 요소를 새로 만들어, 오른쪽에서 왼쪽으로 되돌아가지 않고 다음 줄 왼쪽 끝에서 바로 시작합니다.

## 제거됨

- **메모·타이머·스톱워치·포모도로:** 사용자가 다시 쓰지 않을 기능으로 결정해 화면, 트레이 메뉴, IPC, 저장·알림 코드를 제거했습니다. 기존 `%APPDATA%\Notch\notes.json` 및 `%APPDATA%\Notch\timer.json` 파일은 삭제하지 않고 보존합니다.
- **AI 상태 (Freebuff):** 사용자 요청으로 제거했습니다. 상태 점, 가장자리 선 애니메이션, CTX·PRJ 표시, Freebuff DB 읽기 코드가 모두 빠졌습니다. Freebuff 작업 중 여부는 로컬 DB 신호로 판정할 수 없었습니다.
- **배터리 점:** 색이 있는 점으로 배터리 상태를 보여주는 안은 폐기했습니다(사용자 결정). 노치 모양을 바꾸지 않는 현재 방식(`LOW` 배지·충전 번개·펼친 화면 문구)만 사용합니다.

## 구현 순서

### 1. 미디어 (최우선 표시)
- **데이터 출처:** Windows 미디어 세션(GSMTC). 스포티파이 데스크탑 앱과 브라우저의 유튜브 탭이 모두 여기에 재생 정보를 등록합니다.
- **스포티파이 (실측):** 제목, 아티스트, 앨범, 앨범 아티스트, 트랙 번호, 썸네일(앨범 아트)을 받습니다.
- **유튜브 (실측, 웨일 브라우저 탭):** 제목은 영상 제목 그대로(`[가사/해석/lyrics]` 꼬리표 포함), 아티스트는 채널명, 앨범은 없고 썸네일은 영상 썸네일입니다.
- **세션 선택:** 미디어 세션이 여러 개 잡힙니다. 재생 중(Playing)인 세션을 우선 표시합니다.
- **재생 소스 직접 선택:** 재생 세션이 둘 이상이면 NOW 화면에 앱/탭 버튼을 나열하고(같은 앱의 여러 탭은 `CHROME·1`처럼 번호를 붙임), 사용자가 고른 세션을 자동 선택보다 우선합니다. 고른 세션이 사라지면 조용히 자동 선택으로 돌아가고 버튼 줄은 숨깁니다.
- **가사 출처 (결정):** LRCLIB 등 공개 가사 DB에서 제목과 아티스트로 조회합니다. 미디어 세션 API에는 가사가 없습니다. 키 필요 여부와 정확한 API는 구현 전에 확인합니다.
- **판본 고르기:** 같은 곡이 원문(한글)과 로마자 표기로 따로 올라와 있어 정확 조회만으로는 로마자가 잡힐 수 있습니다. 정확 조회 뒤 검색 API도 한 번 더 확인해, 점수가 같으면 한글 가사 → 줄별 시각이 있는 가사 → 재생 길이에 가까운 가사 순으로 고릅니다. 레이블 채널이라 아티스트를 못 얻으면 제목 앞부분(`aespa 에스파 'Supernova'`)에서 아티스트를 추정하고, 아티스트를 모를 때는 제목과 재생 길이(±5초)로 맞춥니다.
- **펼친 패널 (결정):** 가사 중심으로 표시합니다. 제목, 아티스트, 앨범(있을 때만)은 가사와 함께 보여주고, 재생/일시정지, 이전, 다음 버튼을 붙입니다.
- **싱크 가사 강조 (결정):** 애플뮤직처럼 재생 위치에 맞는 줄을 크고 밝게 표시하고, 나머지 줄은 흐리게 둡니다. 현재 줄은 패널 가운데에 오도록 부드럽게 스크롤합니다. 싱크 가사(LRC 타임스탬프)가 없는 곡은 평문 가사를 그대로 보여줍니다. 일시정지 중에는 위치를 멈춥니다.
- **가사가 없을 때 (결정):** "가사를 찾지 못했습니다." 문구 대신 유튜브 검색 썸네일을 가사 영역에 꽉 차게 깔아 보여줍니다. 썸네일을 못 받으면 앨범 아트로 돌아가고, 그것도 없으면 비워 둡니다.
- **가사 포인트 조명 (완료):** 앨범 아트나 영상 썸네일에서 추출한 대표색의 빛살을 가사에 표시합니다. 색을 추출할 수 없거나 유효하지 않은 표지색이면 고정 주황색을 사용하며, 노치 주변 글로우 효과는 사용하지 않습니다.

### 2. 미디어 / 시스템 상태
- 미디어가 없을 때 펼친 HUD에 시각·날짜, CPU 온도, 데스크탑 GPU 사용률, 날씨를 표시합니다.
- 다음 일정 표시는 캘린더 연동이 필요해 보류합니다.

### 4. 후순위 (조사 또는 결정 후 진행)
- **자동 덕킹:** 회의 앱이 소리를 내면 음악 앱만 잠시 낮추고, 끝나면 원래 음량으로 되돌립니다. 복구 시점과 "사용자가 직접 만졌을 때는 복구하지 않기" 규칙을 먼저 정해야 해서 앱별 수동 제어 뒤로 미뤘습니다. 앱별로 켜고 끄는 옵션으로만 넣습니다.
- 사용량 링: 무료 사용 잔량을 읽을 로컬 데이터가 있는지 먼저 확인합니다.
- 로보 화면 질문: API 키 설정 방식을 먼저 정합니다.
- 캐릭터 꾸미기: 디자인 결정이 먼저 필요합니다.

### 5. 보류
- 블루투스 오디오 연결·기본 출력 전환: 이미 페어링된 기기의 재연결이 한 번에 되지 않는 경우가 많아(사용자 경험상 한두 번 더 눌러야 연결됨) 실패를 보장할 수 없다는 이유로 넣지 않기로 결정했습니다. Windows에는 드라이버에 연결을 "시도"하라고 요청하는 `KSPROPERTY_ONESHOT_RECONNECT`만 있고 성공을 보장하지 않습니다.
- 승인 (Allow/Deny): Freebuff 쪽 외부 응답 인터페이스가 확인되지 않았습니다.
- 로보 파일 자동 수정: 노치의 역할을 넘고 안전 문제가 있어 제외를 권합니다.

## 확인 필요
- 없음. 가사는 LRCLIB 공개 API(`/api/get`·`/api/search`)를 키 없이 사용합니다.

## 규칙
- 한 번에 한 묶음만 구현합니다.
- 기능마다 빌드(`npm run build`)를 통과시킨 뒤 다음으로 넘어갑니다.
- 커밋은 사용자 확인 후 진행합니다.
- exe는 두 가지로 만듭니다. 작업 중 확인은 `npm run pack`(`release\win-unpacked\Notch.exe`, 약 15초)으로 하고, 파일 하나로 옮길 때만 `npm run dist:win`(portable `release\Notch.exe`, 약 4분)을 씁니다. 둘의 차이는 마지막 7z 압축 단계 하나뿐이고, 압축을 건너뛴 쪽이 실행도 더 빠릅니다.
